# Design notes

Why it is built this way, including the parts that are not built yet. Each note opens with
a status block saying which is which, because a design note that reads like documentation
is how somebody comes to depend on something that does not exist.

These are the arguments, not the instructions. For the instructions see the
[guide](../guide/).

- [Policy](policy.html) — the folder, the model call, the answer's schema, the post-processor
- [Testing a policy](policy-testing.html) — what is determinate and what is judgement
- [Budgets](budget.html) — credits, rolling windows, and why there is no timezone
- [Identity and access](auth.html) — tickets, and the credential story that is still owed
